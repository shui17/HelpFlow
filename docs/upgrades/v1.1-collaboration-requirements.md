# 阶段12客服协作与站内通知

本升级依据桌面《Python后端与HelpFlow项目学习路线》中阶段12要求，在 V1.0 工单闭环上增加转交、内部备注、持久化通知，保留现有角色与原子领取机制。

## 业务与权限

当前负责客服可将未关闭工单直接转交给其他启用客服，必须填写 1 至 500 字原因。转交不改变状态，日志记录前后负责人和原因。旧负责人即时失去查询、回复、备注和状态操作权限；新负责人可查看历史公开回复和内部备注。管理员继续使用分配接口。

内部备注与公开回复使用同一表，新增 visibility 字段，默认 public 兼容既有记录。内部备注仅允许当前负责客服和管理员访问，关闭后仅可阅读。公开回复查询在数据库过滤 visibility；普通用户不能通过备注接口、回复分页游标、时间线原因或通知内容读取内部协作信息。

通知在分配、重新分配、转交、用户公开回复和客服公开回复时创建。分配与转交通知新负责人；用户回复通知当前负责人，客服回复通知创建人。领取和内部备注不通知。通知只保存固定消息与工单 ID，不保存回复或内部备注正文。点击通知重新通过工单接口验证访问权限；通知记录本身不授予工单权限。

## 事务和并发

分配及转交依次锁目标客服行与工单行，与已有领取和用户管理保持锁顺序。工单行锁取得后重新检查负责人和状态；转交竞争时旧负责人第二次请求返回 409。日志、负责人及通知写入同一事务，任一写入失败整体回滚。

通知唯一键为 event_key 与 recipient_id，事件键使用 activity:日志ID 或 comment:回复ID。重复事件通过唯一约束和嵌套事务去重，不吞掉其他数据库错误。该机制保证同一业务事件重复投递的幂等；客户端重复提交公开回复仍会产生两个独立回复事件。

通知列表与未读数只查询当前用户；标记已读按通知 ID 和当前用户联合查询，加锁后保留第一次 read_at，重复调用返回相同结果。第一版使用 30 秒轮询。

## 数据与统计

迁移 003_collaboration 增加备注可见性、过滤索引、transferred 日志类型和 notifications 表。转交原因复用日志 description。存在内部备注时拒绝回退到不支持可见性的旧版本；检查在任何回退 DDL 前执行，防止私有数据变公开。回退后转交记录保留为重新分配。

沿用 GET /tickets/summary 的数据库聚合。普通用户按创建人过滤，客服状态与最近工单仅统计本人负责、待领取数量单独统计，管理员统计全局；最近工单使用 LIMIT 5。首页不遍历分页接口。性能脚本对同一用户、相同数据比较分页与聚合，记录请求数、响应体字节、五轮耗时和 EXPLAIN；实际执行结果另行保留，不预设提升幅度。

## 交付与验收

交付迁移、接口、Vue 转交和备注界面、通知页及未读数、回归测试、演示初始化、OpenAPI 与运行说明。范围不包含 SLA、Redis、消息队列、实时推送和 RAG。

验收包括用户创建、客服领取、内部备注、转交、新负责人公开回复、用户确认关闭；并发转交、转交与分配和关闭竞争；旧负责人越权、通知归属、备注泄漏；通知和日志异常整体回滚、事件去重和重复已读。已验证与待验证项目见阶段12指南。
