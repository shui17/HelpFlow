# 前端运行与验证

## 本地启动

使用 Node.js 22.12+ 或 24 LTS，在仓库根目录执行：

```powershell
cd frontend
npm ci --legacy-peer-deps
Copy-Item .env.example .env
npm run dev
```

打开 `http://localhost:5173`。后端按数据库、安全指南初始化后运行于 `http://localhost:8000`。前端使用 `VITE_API_BASE_URL`，修改后需重启 Vite。开发端口固定为 5173，与后端默认 CORS 配置一致；更换访问域名或端口时同步调整 `HELPFLOW_CORS_ORIGINS`。

```powershell
npm test
npm run build
npm run preview
```

生产发布时将 `dist` 作为静态目录，并配置所有前端路由回退到 `index.html`。生产域名需加入后端 CORS；预览默认使用 4173，也需要加入 CORS 才能请求后端。

## 当前接口适配

前端遵循 `docs/architecture/frontend.md` 的 Vue 3、JavaScript、Pinia、Axios、Vue Router、Element Plus 方案。共享工单列表和详情按角色配置路由及操作，认证之外的数据保留在页面中。

- Axios 解包 `{code, message, data}`，统一注入 Token；401 清除失效会话并返回登录。错误由页面显示一次。
- 工单标题最多 200 字、描述最多 5000 字、回复最多 2000 字，与实际 Schema 一致。
- 分类创建、编辑和筛选已接入后端；个人中心和用户管理显示注册时间。工单使用 ID 展示；概览由当前角色可见的工单集合计算。
- 所有工单列表使用后端分页，客服范围通过 `scope=mine/unassigned` 筛选，管理员通过 `assignee_id` 或 `unassigned` 筛选。概览使用 `/tickets/summary` 聚合接口，不再遍历全部工单；客服选择框使用后端关键词搜索。回复和时间线默认加载最近 50 条，可按需加载更早记录。
- 管理员分配选项从全部启用客服分页获取；角色管理不提供创建管理员入口。
- 正文、回复、时间线描述均使用纯文本插值。状态操作、领取、撤销、分配及用户管理均二次确认，提交期间防止重复操作。

## 浏览器验收清单

在 1366×768、1440×900 下检查布局、表格横向滚动、弹窗和菜单折叠。后端需要真实 MySQL、迁移和三种角色账号，才能完成真实联调：

1. 注册用户并登录，刷新详情页后仍能恢复会话；直接访问其它角色路由显示 403。
2. 创建、筛选、搜索、分页、编辑、撤销未分配工单；空结果和接口错误都有反馈。
3. 客服在待领取列表领取，再进入本人列表开始处理、回复并标记解决。两个客服同时领取时失败方显示后端冲突原因并刷新。
4. 用户回复、重新打开，再由客服解决，用户确认关闭。关闭后回复和状态按钮消失。
5. 管理员查看全局工单和时间线，分配、重新分配给启用客服；不能发送回复或绕过状态流程。
6. 管理员搜索与筛选用户，调整用户/客服角色，启用/禁用账号；保留后端对未关闭工单的限制提示；当前管理员不能禁用自己。
7. 修改密码后回到登录页；过期 Token 返回登录页；断开后端时显示连接失败和重试入口。

自动化单元测试覆盖权限矩阵、跨页筛选、登录恢复、失效 Token 清理和登录失败回滚。构建检查负责 Vue 模板和模块依赖验证；不能代替真实数据库与多角色浏览器联调。

自动化验证步骤见 [测试与持续集成](verification.md)。
