## 环境与运行

本次使用 Python 3.14、Node.js 24、MySQL 8.0.46。隔离 MySQL 监听 `127.0.0.1:3309`，演示库为 `helpflow_demo_stage9`，测试库为 `helpflow_stage5_test_stage9`；没有修改系统原有 MySQL 服务和业务库。

后端读取被 Git 忽略的 `backend/.env`。数据库连接、随机 JWT 密钥、演示密码仅保存在本地忽略目录，不写入仓库。当前演示账号密码见本机 `backend/.uv-cache/stage9/demo-credentials.txt`，账号邮箱见 README。

本机恢复隔离 MySQL：

```powershell
cd backend
.\.venv\Scripts\python.exe .uv-cache/stage9/manage.py start
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`manage.py status` 检查实例，`manage.py stop` 关闭该隔离实例。新机器不依赖此缓存目录，按 [README](../../README.md) 创建自己的数据库、执行迁移及演示初始化。

## Apifox 导入资料

- [OpenAPI 契约](../api/helpflow.openapi.json)：从实际 FastAPI 应用生成，包含 19 个接口路径及分类、注册时间等 Schema。更新命令：在 backend 执行 `python -m scripts.export_openapi`。
- [业务场景集合](../api/helpflow-workflow.postman_collection.json)：Postman v2.1 格式，包含 21 个正常与异常请求，供 Apifox 导入；场景包含登录、分类工单、领取冲突、双方回复、重新打开、关闭、权限及校验错误。

导入集合后设置 `base_url=http://localhost:8000/api/v1`，在本地环境填入 `demo_password`；三个角色登录脚本保存对应 Token，创建工单保存 `ticket_id`。集合不保存真实密码和 Token。接口导出文件已生成，客户端导入兼容性和 Runner 结果仍需在 Apifox 中确认。
