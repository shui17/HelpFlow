# JWT 权限与安全

> 历史设计记录：文中的实现范围反映当时版本；当前目录与依赖以 [文件职责图](../file-map.md) 为准。
依据学习路线阶段 6、PRD 和后端认证设计，按本次“进行阶段六的代码实现”指令实施。不创建 Git 提交。

采用现有 Router、Service、Repository 结构，增加 pwdlib Argon2 密码工具、固定 HS256 的 PyJWT 工具、认证和角色依赖。另一方案是在路由中直接处理认证与权限，会重复规则；本阶段采用集中工具与 Service 资源权限检查。

注册要求用户名 2–30 字、密码 8–64 字且包含字母和数字、确认密码一致。密码不裁剪空白，邮箱转小写。新增登录、当前用户、修改密码。Token 默认两小时，要求 sub、role、iat、exp；每次请求读取当前数据库角色和启用状态。额外用密钥 HMAC 生成密码版本标识，修改密码立即使旧 Token 失效，不增加数据表字段。缺失、伪造和过期 Token 返回 401；禁用及越权返回 403。JWT 密钥从环境提供，至少 32 字节，无弱默认值。

公开入口仅注册、登录和健康检查；旧 POST /users 创建入口移除。管理员可查询用户并修改 user/agent 角色和启用状态，禁止修改管理员角色、自我禁用以及降级或禁用仍有未关闭工单的客服。本阶段一并写入已有用户管理日志表，与更新同事务提交。

工单创建人、回复人从当前用户取得，请求拒绝伪造 ID。普通用户仅可查询自己的工单；客服只可查询本人负责或 open 且无负责人的工单；管理员可查询全部。修改仅允许创建者，回复仅允许创建者或负责客服；状态修改按数据库当前角色和归属限制。保留 PATCH 状态路径。领取分配、撤销、完整状态业务和工单活动留至阶段七。

认证读取使用请求 Session 的短事务，在业务服务事务开始前结束，避免隐式开启事务与 begin 冲突。管理员初始化脚本安全读取密码、幂等创建，不自动升级既有普通用户。应用启动检查密钥，迁移无需密钥。

验证覆盖 Argon2、JWT 失效、错误响应脱敏、登录与密码变更、角色和账号即时生效、资源越权、管理限制和回滚。使用隔离 MySQL，不修改已有业务数据库。更新环境示例、阶段六指南和文件关系图。
