# 阶段十五：客服业务 Agent 设计

## 已确认目标

用户同意实现范围较小、执行可靠的单 Agent：先完成交接摘要经确认保存内部备注，再完成知识检索后拟公开回复、经确认发送。沿用已配置的 DeepSeek 与 Embedding，以及现有 MySQL、认证、工单权限和知识库。此前允许跳过缺失的 writing-plans 技能的授权继续沿用。

依据桌面学习路线，工具选择必须由模型结合工具结果动态决定；只串联固定接口不能报告为 Agent。交付还须包含 LangGraph 持久化检查点、人工确认、中断恢复与业务去重。

## 方案比较与选择

1. 推荐 LangGraph 单 Agent 工具循环，开发期 SQLite 持久化检查点，MySQL 保存业务任务和确认执行记录。符合学习路线，检查点与业务事务分开治理。
2. 自建 MySQL 状态机可以减少依赖，但不覆盖路线中 LangGraph 的学习目标，本次不采用。
3. 多 Agent 或完整任务队列增加部署、协调与重试复杂度，当前两条流程不需要。

具体 LangGraph 版本及 Python 3.14/异步 SQLite 兼容性在实现前核对官方文档并锁定依赖；如运行环境不兼容，先记录阻塞，不默默降级为固定工作流并宣称全部完成。

## 产品流程与范围

当前负责客服在工单详情选择“整理内部交接摘要”或“拟公开回复”，输入补充要求后启动任务。前端展示工具进度、资料来源、草稿、待确认内容与最终结果；支持编辑待确认内容、拒绝、取消、刷新恢复。

交接摘要包含问题、已尝试步骤、当前结论及待办；缺失信息明确标记未知，不能补造已完成的操作。第一版不转交、不改状态、不自动关闭工单。原人工回复、内部备注与阶段十四草稿入口保留。

公开回复与内部摘要在创建任务时分别绑定用途，禁止在同一任务里切换用途。公开回复任务的工具上下文不读取内部备注，内部摘要也不能通过修改工具名或确认参数改成公开回复。用户输入和资料中的指令不会获得执行权限。

## 工具与模型循环

白名单只读工具：查询当前授权工单、分页读取该工单沟通记录、检索公开知识。模型可根据问题选择调用、继续查询、请求补充信息或结束。内部摘要任务允许读取内部备注；公开回复任务只能读公开沟通记录。所有工具从服务端绑定的工单和用户获取身份，不接受模型指定其他用户或任意工单ID。

提交待确认内容使用“提出备注/回复建议”工具，它只创建提案，不执行写入。公开回复的引用必须来自该任务实际检索结果；没有足够依据时结束为需要补充信息，不凭空生成政策或承诺。内部摘要使用工单事实，可不依赖知识检索；展示本轮读取记录的覆盖范围。

工具参数由 Pydantic 严格校验，多余字段拒绝；仅允许固定名称，不执行模型返回的任意 Python、SQL、URL 或文件操作。工具结果重新交回模型决定下一步。

默认最多6轮模型调用、8次只读工具调用；单次外部调用沿用模型超时，单轮执行总预算180秒。记录耗时、工具名称、脱敏参数摘要和有限长度的工具结果。超限、未知工具、非法参数与重复无进展调用受控终止。数据库事务不跨越模型请求。

## 持久化、确认和恢复

MySQL新增任务与执行记录。任务保存随机ID、创建客服、绑定工单、用途、状态、提案版本、草稿、来源、上下文指纹、确认到期时间、结果ID和错误分类。检查点使用服务端随机任务ID作为 thread_id，不接受用户任意指定其他检查点。

LangGraph检查点保存有限的模型消息、已执行只读工具结果和待确认状态。SQLite位于忽略的本地运行目录，包含工单内容，不进入Git；通过已授权应用接口访问。第一版面向单机部署，不能将本地SQLite描述为跨主机高可用方案。

任务状态：准备/运行、等待补充信息、等待确认、成功、失败、已拒绝、已取消、已过期、上下文失效。用户重新执行时使用相同任务ID；模型或工具失败后的继续执行有明确入口和剩余预算，不自动产生无限重试费用。

创建接口接受客户端请求ID并以用户和请求ID唯一约束去重；同ID不同输入拒绝。处理中的任务使用数据库租约与执行代数约束一个有效执行者。执行者失联后可恢复，旧执行者必须通过代数校验才能保存结果，避免迟到结果覆盖新结果。

等待确认的任务可在进程重启或页面刷新后恢复。已经保存的提案不重新调用模型。检查点丢失但MySQL任务已成功时，以业务执行记录恢复结果；未成功且检查点无法恢复时明确失败，不能猜测已执行。

提案默认15分钟有效，绑定客服、工单、用途、内容哈希和提案版本；页面展示实际目标、全文和公开/内部属性。编辑内容生成新版本并要求重新确认，旧确认版本拒绝。确认接口只接收任务ID和提案版本，不允许同时携带未经展示的新内容。

## 写入事务与权限

执行前重新检查账号启用、角色仍为负责客服、工单未关闭，以及状态、负责人、沟通记录和业务活动指纹未变化。变化使原提案失效，要求刷新任务生成新提案。指纹使用记录ID和内容/状态，不能只依赖秒级 updated_at。

知识版本用于公开回复时，也检查引用版本仍有效；失效要求重新生成。拒绝、取消、过期的提案不能执行。任务查询、恢复、编辑与确认全部核对任务归属和当前工单权限，转交后的旧客服不能读取任务中的旧摘要或结果正文。

复用 TicketService：提取其备注/回复写入的事务内方法，原接口继续负责建立事务与提交后调度。Agent执行器在一个MySQL事务内锁定并校验用户、工单和任务，调用相同业务方法，写入唯一操作记录与成功结果。锁顺序统一为用户→工单→任务；涉及同类资源的Agent入口保持该顺序。

唯一操作键绑定任务和提案版本。确认并发、重复点击、提交成功但响应丢失时，返回同一结果ID，不重复创建备注/回复、通知或SLA事件。已完成任务仍须先验证当前访问权限再返回结果。失败回滚同时撤销业务写入与操作记录，重试才可重新执行。

模型调用与检查点本身不保证业务写入仅发生一次，业务幂等由上述唯一键和MySQL事务提供。公开回复正常触发原有通知与SLA；内部备注不触发公开响应SLA。Redis更新仍在提交后进行，失败依赖已有数据库补偿。

## 前端与接口分工

新增独立Agent任务路由与Service、工具适配层、LangGraph编排、模型Tool Calling适配器、任务模型与迁移。前端新增任务面板及API模块，详情页仅挂载组件，避免把执行状态逻辑堆进现有详情页面。

接口覆盖创建、查询当前工单任务列表/任务状态、继续执行、编辑提案、确认、拒绝和取消。任务列表仅返回当前用户且仍有权限的工单任务，限制分页。前端以服务端状态为准，确认按钮防重复只是交互优化，不承担业务去重职责。

发生HTTP超时后先查询原任务状态；等待确认显示准确正文，成功显示实际保存的备注/回复ID，不能将模型说“完成”当成业务成功。切换工单丢弃迟到响应。

## 验收与交付边界

- 单元与接口测试：工具选择、参数验证、未知工具、步数/时间上限、模型异常和缺少资料；固定模型替身不当作真实模型效果。
- 权限测试：普通用户、非负责客服、停用账号、转交/关闭后执行、任务归属、伪造确认；公开工具与提案不能携带内部备注内容。
- MySQL测试：确认并发、拒绝/过期/编辑旧版本、写入异常整体回滚；提交成功但响应前中断后重复确认，业务记录和通知数量保持不变。
- 持久化测试：等待确认时关闭并重建进程/检查点连接，再次查询同任务可以继续；执行租约过期、旧代数迟到结果、检查点与业务提交之间故障可恢复。
- 浏览器测试：生成摘要、编辑、明确确认、备注展示；公开回复确认发送；取消/拒绝、刷新恢复和重复点击。原阶段12～14流程继续回归。
- 固定任务集包含只查询、需要检索、需要澄清、内部摘要及公开回复，记录真实模型、配置、工具选择错误、任务完成情况、调用次数及耗时；不预设成功率。
- 先在独立测试库验证迁移；演示库升级前备份。真实模型调用只使用公开测试知识和合成工单，不对真实用户自动发送消息。

交付运行指南、环境配置、状态图、迁移、接口文档、回归测试与原始评测记录。只有工具循环、确认执行、持久化恢复和防重复写入均验证后，才将阶段十五标记为完成；尚未验证的条目明确列出。
