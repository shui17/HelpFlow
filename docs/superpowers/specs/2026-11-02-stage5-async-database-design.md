# 阶段五异步数据库接入方案

状态：用户已确认，已实现并通过隔离 MySQL 验证。依据学习路线阶段五及当前阶段三 API、阶段四 SQL。

## 目标与边界

将现有 HTTP 接口的数据存储替换为 MySQL，使用 SQLAlchemy 2.x 异步接口、asyncmy、Alembic。保留阶段一和二独立练习。阶段四的 helpflow_stage4 学习库保持独立；阶段五使用配置指定的新数据库 helpflow，不导入或修改阶段四数据。

本阶段保留现有注册、用户查询、工单创建、列表、详情、修改、状态变更和回复接口的路径及响应结构。工单分类暂以 other 写入，工单号由后端生成；输入输出字段暂不扩展。注册仍固定普通用户，不接收密码，数据库中使用明确无效且不可登录的密码占位值。登录、JWT、数据权限及完整领取状态业务仍在阶段六、七实现。

## 代码结构

- app/db/：声明式基类、AsyncEngine、async_sessionmaker、请求级 Session 依赖。
- app/models/：五张表的 ORM 模型、外键、关系、约束与索引。
- app/repositories/：用户、工单与回复的数据访问和查询；不自行提交事务。
- app/services/：沿用现有业务规则的异步服务，明确控制写入事务。
- app/routers/：改为 async def 并 await 服务调用，继续复用 Pydantic Schema。
- alembic/ 与 alembic.ini：迁移环境、版本脚本和数据库元数据。

旧内存 Service 仅用于早期独立练习，不在正式 API 中提供双存储切换。

## 生命周期和一致性

每个请求获得独立 AsyncSession，失败回滚、结束关闭，不在并发任务之间共享 Session。写操作必须在响应成功前完成提交。引擎通过应用生命周期释放。查询在 Repository 中使用绑定参数、SQL 筛选排序分页与 count；显式选取或加载所需关系，避免序列化期间隐式 IO 和 N+1。

邮箱保留预检查，同时将数据库唯一冲突转换为现有 409；其他约束错误按上下文处理，未知数据库异常返回脱敏 500，不泄露连接串或密码。兼容数据库 DATETIME 的 UTC 约定，响应维持既有时间语义。

## Alembic

从空库迁移创建五张表，结构以阶段四为依据。基线迁移先创建 tickets 的其他字段，下一版迁移单独增加 updated_at，最终结构与阶段四一致；由此实测“增加字段、升级、回退、重新升级”，不增加业务功能。迁移不写示例账号或数据，应用启动不调用 create_all，不自动升级或删除表。autogenerate 结果必须人工检查。

现有手工建表库不直接 stamp 为已迁移；本阶段使用明确的新空库验证，既有库接管需另行核对差异。
